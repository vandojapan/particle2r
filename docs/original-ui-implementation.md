# 旧版 UI の再現に必要な作業

対象はパーティクル(R) ver3.54B の 32 効果。画面と設定値の一次資料は `particle_r_evidence/parameters.json` と同梱の旧スクリプト。AviUtl2 で確認する際は `aviutl2-cli` の開発ポータブル版を使う。

## 0.8.0-beta.2 の到達点

- [x] 効果追加メニューの「パーティクル(R)」ラベルに、旧版の「パーティクル本体」と31拡張を登録する。「加工」には登録しない。AviUtl2標準効果と衝突する「回転」「テキスト」の登録名だけは `[パーティクル(R)]` を付けた。
- [x] 各効果のトラック数、表示名、範囲、初期値、最小操作単位を元スクリプトから生成した。旧資料の合計 104 トラックをテストで照合する。
- [x] チェック項目とファイル選択を表示する。旧 `--dialog` は折り畳みグループ内の個別入力欄として、元ラベル・Lua変数名・初期値を表示する。
- [x] 標準「スクリプト制御」のコードを読み、説明書の `xyz` / `xyzd` / `vector` 自作関数を「出力」「挙動」から実行する。取得できない場合の直接入力欄も両効果に追加する。
- [x] 複数の「パス」で1～10番へ外部 `.txt` / `.lua` を登録し、説明書と同じ「出力」の数・オプション、「挙動」の取得パス番号から自作関数を実行する。
- [ ] 旧版と同じ設定操作（トラックの時間変化、複数の同名効果、効果の有効化、設定ダイアログの確定／取消）を保存・再読込を含めて確認する。
- [ ] 32 効果の各設定をレンダラーへ接続し、項目ごとに旧版の出力と比較する。未接続の項目を操作可能な完成機能として公開しない。
- [ ] 記事の各例を旧版と同じ効果名・操作順・値で作り、AviUtl2 の出力を比較する。

## 現時点で分かった制約

旧 `--track0` と `--check0` は AviUtl2 の Lua 互換モードで読み込める。一方、旧 `--dialog` は個別の設定項目に展開され、旧版の設定ダイアログにはならない。0.8.0-beta.2 はこの AviUtl2 の方式に合わせ、折り畳みグループに全項目を表示する。32bit の旧 DLL は現在の 64bit `.auf2` の描画処理としてそのまま読み込めない。

UI 定義は `scripts/generate_legacy_ui.ps1` が `parameters.json` から `legacy_ui_data.rs` を生成する。元資料にある表記揺れや括弧の欠落も、記事・スクリプトとの検索性を優先して保持している。

## 実装手順

1. ~~`parameters.json` から旧 UI 定義を生成し、32 件の名前、104 トラック、チェック、ダイアログ項目を機械的に照合する。~~ 実装済み。
2. ~~AviUtl2 のネイティブ設定項目へ旧トラック、チェック、詳細設定を配置する。~~ 実装済み。専用ポップアップではなく折り畳みグループを採用した。
3. 現在の描画コアへ渡す値を、旧値の単位と意味で受けるアダプターへ順次追加する。0.8.0-beta.2 では本体、主要拡張、スクリプト制御、パス番号による数値Lua・画像・テキスト・ファンネル画像を接続済み。
4. 不足する 8 効果と既存 23 拡張の未実装パラメーターを実装する。各項目の効き方を旧 AviUtl 1.x 上の ver3.54B と同じ入力素材・フレームで比較する。
5. `au2 develop --skip-start` で配置し、AviUtl2 2.1.9 の起動ログで32プラグインと32効果が登録エラーなしで読み込まれることを確認済み。次は UI の保存・再読込と出力画像を確認する。

描画処理の対応範囲は `docs/compatibility.md` を参照する。UI に項目が存在することと、その計算処理が移植済みであることは別に扱う。
